# Remote contract inventory

Every `@Remote` verb `ResearchService` exposes (92 total), grouped by domain,
with its request payload, result type, and the panel-side consumer (the
`ResearchRemote` facade in `packages/ui-mimir/src/client/controller.ts`).
Generated by manual audit for #245; update it whenever a verb, a request
field, or a failure code is added or removed.

Conventions:

- All results are `ResearchResult<T>` — `{ ok: true, value }` or
  `{ ok: false, error }`; the panel unwraps the transport/business double
  envelope via `unwrapRemote` (#251).
- Request fields marked `?` are optional on the wire; dropping an optional
  field is backward compatible, adding one is too (older hosts ignore it).
- Verbs whose panel consumption reads "—" have no UI caller. The four under
  "Insight" are `@experimental` in `service.ts`: shipped for programmatic
  hosts, subject to change without notice.

Cleanup landed with this inventory (#245):

- `updatePaper.relevance` removed — no client ever sent it; relevance
  verdicts are written by the agent's `wiki_note set_paper` action (which
  validates the 0–10 score and the project link), and the panel only reads
  `paper.relevance` views.
- `checkArxivSubscriptions` is now parameterless — the panel only ever sent
  `{}`. The single-subscription recheck (`{ id }`) survives in the internal
  `services/subscriptions.ts` API for future use.
- `addEvidenceEdge` removed from the panel's `ResearchRemote` interface
  (declared, never invoked); the host verb stays — edges are declared
  through the agent's `wiki_note` tool.
